## 1. 구현 목표와 우선순위

현재 임시 로비를 **세 영웅이 함께 머무는 밝은 3D 캠프 + 정돈된 원정 출발 시트 + 5개 하단 메뉴**로 교체한다. 기능 배치뿐 아니라 캐릭터 크기, 원근, 배경 깊이, 재질, 그림자, 버튼의 얕은 입체감, 글자 위계까지 기준 이미지의 완성도에 맞춘다.

화면 상단은 **골드·강화석·시간의 결정 HUD와 설정 버튼**으로 구성한다. 중앙은 파티와 캠프, 우측은 미션·출석 두 버튼, 하단은 원정 선택과 출발, 끝없는 행군 링크, 고정 내비게이션으로 구성한다. 아래 구성 요소 명세가 구현 대상의 전체 목록이다.

우선순위는 다음과 같다.

1. 얼굴과 실루엣이 잘 보이는 세 영웅, 모닥불, 보상 상자.
2. 가장 강하게 읽히는 노란 `출발` 버튼과 한 줄로 이해되는 원정 선택.
3. 정돈된 재화·설정·보조 메뉴와 하단 5개 메뉴.
4. 부드러운 배경 원경, 소품, 은은한 대기 움직임과 피드백.

위치를 대략 맞춘 기능 시제품에서 끝내지 않는다. 현재의 작은 원형 섬, 강한 검정 외곽선, 원색 대형 카드에 새 버튼만 얹은 결과는 목표에 미달한다. 구현 완료 판정은 **실제 게임 캡처를 컨셉과 나란히 비교**해서 내린다.

## 2. 작업 범위

### 반드시 구현

- 로비 전체 레이아웃 재구성 및 모바일 세로 화면 대응.
- 세 영웅·캠프·원경을 포함한 로비 전용 3D 아트와 카메라 조정.
- 재화 캡슐, 설정, 미션·출석, 보상 상자와 라벨, 원정 시트, 하단 내비게이션의 스타일과 입력.
- 실제 저장 데이터, 기존 화면 열기, 원정·행군·토벌 진입 연결.
- 수령·합성 상태 표시, 화면 복귀 시 갱신, 중복 입력 방지.
- 새 로비 리소스의 빌드 포함, 실행 파일 갱신 및 캡처 증거.

### 기존 동작을 재사용

장비 강화·합성, 유물 장착·합성, 탤런트, 일일·주간 미션, 출석, 방치 보상, 토벌의 계산·지급·저장 규칙은 유지한다. 이 화면들 내부의 전면 재디자인은 이번 로비 작업의 필수 범위가 아니다. 로비에서 접근하고 정상적으로 돌아올 수 있어야 한다.

전투·드롭·수치 밸런스·챕터 해금·보상량·일일 횟수·저장 포맷을 로비 표현 변경과 함께 바꾸지 않는다. 신규 재화, 에너지, 상점, 패스, 길드 등은 추가하지 않는다.

## 4. 권장 구현 구조

파일을 전부 `lobby.gd`에 추가하지 말고 표현을 분리한다. 아래 이름은 **신규 제안**이며 현재 존재하는 API가 아니다.

```text
Lobby (기존 씬 / 연결·수명 관리)
├─ LobbyCampStage (로비 전용 3D 장면)
│  ├─ Environment / Camera / Lights
│  ├─ DistantScenery
│  ├─ CampGround / Trees / Crystals / Flowers
│  ├─ Warrior / Ranger / Mage
│  ├─ Campfire
│  └─ RewardChest / LabelAnchor
└─ CanvasLayer
   └─ LobbyView
      ├─ SafeArea
      │  ├─ TopHud / SettingsButton
      │  ├─ MissionButton / AttendanceButton
      │  ├─ RewardChestHotspot / RewardLabel
      │  ├─ ExpeditionSheet
      │  │  ├─ ModeTab / ChapterRow / Objective
      │  │  ├─ StartButton
      │  │  └─ EndlessLink
      │  └─ BottomNavigation
      └─ ModalLayer (기존 기능 화면을 올리는 층)
```

권장 파일:

- `godot/scripts/lobby_view.gd`: 2D 구성·레이아웃·표시 상태·입력 신호.
- `godot/scripts/lobby_camp_stage.gd`: 캠프·카메라·로비 전용 연출·상자 앵커.
- `godot/scripts/lobby_style.gd`: 로비 전용 색·폰트·StyleBox·아이콘 크기.
- 필요 시 `godot/art/lobby/`: 분리된 아이콘·UI 텍스처·배경 레이어·신규 아트.

`LobbyView`는 `equipment_requested`, `relics_requested`, `camp_requested`, `challenge_requested`, `growth_requested`, `mission_requested`, `attendance_requested`, `settings_requested`, `chapter_step_requested(step)`, `expedition_requested`, `endless_requested`에 해당하는 신호를 내보내는 방식으로 구성한다. 이름 자체는 구현에 맞춰 조정해도 되지만, UI 컴포넌트 안에 보상 지급·저장·전투 진입 로직을 복제하지 않는다.

3D 화면과 보상 라벨은 같은 카메라·앵커 기준으로 연결한다. `Meta`는 데이터·기존 동작의 권위 있는 출처로 두고, 표시용 스냅샷이나 getter로 View에 전달한다.

## 5. 기준 좌표와 반응형 레이아웃

수치는 **720 × 1280 논리 좌표에서 시작할 구현 가이드**다. 이미지에서 측정한 고정 픽셀 계약은 아니다. 컨셉의 시각 비율을 유지하는 범위에서 조정하되, 아래 요소 누락·겹침·의도 변경은 허용하지 않는다.

### 기본 화면 배치

| 구성 | 기준 영역 / 크기 | 기준 |
|---|---|---|
| 상단 HUD | `y=24~112`, 좌우 여백 24 | 재화와 설정 한 줄, 나머지는 하늘로 자연스럽게 연결 |

| 강화석 캡슐 | `(224, 32, 160, 64)` | 파랑 돌 + 값 |

| 하단 내비게이션 | `(0, 1160, 720, 120)` | 5개 균등 칸, 중앙 캠프 선택 |

### 리사이즈·안전 영역

- HUD는 안전 영역의 상단, 내비게이션은 안전 영역의 하단을 기준으로 고정한다.
- 원정 시트는 하단 내비게이션 위에 붙여 배치한다. 노치·홈 인디케이터 공간은 배경으로 채우고 입력 요소는 그 안으로 넣지 않는다.
- 하단부는 한 그룹으로 배치한다. 화면 높이가 바뀔 때 개별 버튼의 절대 좌표가 따로 흩어지지 않게 한다.
- 챕터 제목과 목표의 실제 글자 영역은 겹치지 않게 한다. 화살표의 넓은 입력 영역은 제목·목표의 양옆 공간만 사용한다.
- 긴 세로 화면의 여유는 하늘·원경과 중앙 장면이 흡수한다. 하단 시트와 주 버튼을 세로로 늘이지 않는다.
- 실제 viewport 크기로 2D와 3D 투영을 함께 갱신한다. 720 × 1280일 때 맞춘 카메라를 `expand` 화면에서도 그대로 두어 얼굴·상자 위치가 틀어지지 않게 한다.
- 터치 대상은 원칙적으로 최소 88 × 88 논리 단위 상당을 확보한다. 보이는 모양이 작은 버튼은 투명 입력 여백으로 보완하되, 이웃 버튼·출발·내비게이션의 입력 영역과 겹치지 않는다.
- 좁은 화면에서 글자만 무한히 작게 하지 않는다. 재화 캡슐 안쪽 간격, 숫자 축약, 긴 챕터명 줄바꿈 순서로 대응한다.

## 6. 시각 스타일 규격

### 팔레트

아래 색은 초기 토큰이다. 이미지와 비교해 밝기·채도를 조정하고 로비 스타일 한곳에서 관리한다.

| 역할 | 기준색 | 처리 |
|---|---|---|
| 하늘 | `#8FDDF7` ~ `#C6F0FC` | 밝고 부드러운 세로 변화 |
| 크림 시트·내비게이션 | `#FFF8E8` | 순백 대신 따뜻한 밝은 바탕 |
| 재화 캡슐 | `#174A61` ~ `#12394B` | 어두운 청록, 얕은 하이라이트 |
| 기본 글자 | `#173A4A` | 설명까지 검은 외곽선으로 둘러싸지 않음 |
| 보조 글자 | `#7D817D` | 크림 위에서 읽히는 중간 명도 |
| 선택·원정 탭 | `#33BEBB` | 중앙 캠프와 같은 계열 |
| 출발 상면 | `#FFE74E` ~ `#FFC824` | 노란 주 행동 |
| 출발 아래 턱 | `#D98A1B` | 얕고 부드러운 주황 입체감 |
| 행군 링크 | `#C6E9E2` | 주 행동보다 훨씬 약함 |
| 알림 | `#FF5964` | 작은 원형 점, 기본 정지 |

### 형태·타이포

- 캡슐·버튼은 부드러운 큰 라운드와 얕은 아래 턱을 사용한다. 두꺼운 검은 테두리와 여러 겹 어두운 프레임을 제거한다.
- 그림자는 낮은 불투명도의 짧은 접지 그림자다. 모든 라벨에 그림자나 외곽선을 넣지 않는다.
- 재화 숫자 28~32, 챕터명 36~40, 목표 24~26, 출발 52~60, 하단 라벨 24~26, 보조 버튼 라벨 22~24 논리 크기에서 시작한다.
- 한국어는 둥글고 굵지만 획 사이가 뭉개지지 않는 폰트를 사용한다. `godot/fonts/NotoSansKR-VF.ttf` 등 번들 폰트로 Windows·Web에서 동일하게 재현되게 한다. OS에만 설치된 글꼴에 의존하지 않는다.
- 작은 영문·기호 때문에 한국어 폰트가 바뀌거나 행 높이가 튀지 않게 한다. `출발 ▶`는 텍스트 하나에 의존하기보다 글자와 삼각 아이콘을 분리해 정렬한다.
- 기본 설명·수치에 기존 `_label()` 기본값인 큰 outline이 남지 않게 새 로비 스타일에서 명시적으로 제어한다.
- 한글, 값, 선택 상태, 화살표는 실제 UI로 조판한다. 생성 이미지 속 문자를 잘라 붙이지 않는다.

## 7. 구성 요소별 구현 명세

### 7.1 재화 3종

- 왼쪽부터 골드 / 강화석 / 시간의 결정. 아이콘은 금색 동전 / 파란 면이 있는 돌 / 보라 결정으로 분명하게 구분한다.
- 수치는 각각 `Meta.gold`, `Meta.stones`, `Meta.crystals`. 이미지의 `47,769 / 986 / 1,698`은 비교용 예시이며 런타임에 고정하지 않는다.
- 기본은 천 단위 쉼표 표기. 큰 값은 일정한 정책으로 `1.2M` 같은 축약을 허용하되 데이터는 원래 정수를 유지한다. 0·네 자리·여섯 자리·매우 큰 값 모두 영역 안에 들어와야 한다.
- 아이콘은 약 40~44, 값은 세로 중앙 정렬. 값의 색은 골드=노랑, 강화석=밝은 파랑, 결정=라벤더로 맞춘다.
- 상단 캡슐은 정보 표시다. 실제 연결할 기능이 없으면 재화 상점 버튼처럼 동작하게 만들지 않는다.
- 재화 사용·수령 화면을 닫는 즉시 값이 갱신된다. 숫자 변화 애니메이션을 쓰더라도 최종 실제 값과 어긋나지 않아야 한다.

### 7.2 설정

- 상단 오른쪽, 작은 어두운 청록 원형/둥근 버튼과 흰 톱니 아이콘.
- 기존 `_open_settings()`에 연결한다. 기존 음량 설정과 보존해야 하는 개발 기능은 이 화면의 수명을 따라 유지한다.
- 일반 로비에 UI 프리셋 전환 버튼이나 키보드 종료 안내를 노출하지 않는다. 개발용 동작이 필요하면 기존 설정 내부나 개발 경로로 남긴다.
- 로비 외형은 기존 `classic` / `ttukka` 저장값에 따라 예전 대형 카드 스타일로 돌아가지 않게 한다. 공용 프리셋과 다른 화면의 동작은 임의로 제거하지 않는다.

### 7.3 캠프 장면·원경

- 중심은 원형 받침을 멀리서 내려다보는 전시물이 아니라, **영웅 얼굴이 잘 보이는 가까운 캠프**다. 흙·잔디 바닥은 화면 아래로 이어지고, 시트가 바닥 일부를 덮는다.
- 왼쪽: 크고 둥근 층이 있는 소나무, 뒤쪽 관목, 앞쪽 나무 그루터기.
- 오른쪽: 보라·파랑 수정 군집, 둥근 바위, 작고 단순한 식생.
- 앞쪽: 모닥불 돌테와 장작, 오른쪽의 나무 보상 상자, 소수의 흰·노랑 꽃과 붉은 버섯.
- 원경: 하늘·부드러운 구름, 물길/폭포가 있는 초록 절벽, 먼 성의 실루엣. 캐릭터보다 채도·대비·선명도를 낮춰 깊이를 만든다.
- 원경의 모든 것을 고밀도 3D로 만들 필요는 없다. 실제 3D 중경·전경과 분리된 2.5D 원경 레이어를 조합할 수 있다. 카메라 이동·리사이즈에서 경계가 드러나거나 화면 UI가 함께 구워져 있으면 안 된다.
- 월드 전체를 초록·노랑으로 과노출시키지 않는다. 잔디와 캐릭터 피부·갑옷이 구분되어야 한다.
- 기존 초원/광산 반쪽 섬의 단순 배치를 그대로 보존하는 것은 요구가 아니다. 컨셉에 맞게 소품과 원경을 새로 구성한다.

### 7.4 세 영웅

| 위치 | 유지할 정체성 | 컨셉에서 중요한 디테일 |
|---|---|---|
| 왼쪽 | 워리어 | 은빛 뿔 투구, 흰 수염·콧수염, 주황 옷, 짧고 굵은 검, 둥근 방패 |
| 가운데·약간 앞 | 레인저 | 분홍 머리, 초록 튜닉, 갈색 장화·장비, 활과 화살통 |
| 오른쪽 | 메이지 | 보라 뾰족 모자와 띠, 파란 로브, 푸른 결정 지팡이 |

- 세 명의 머리·몸·발이 구분되고, 얼굴·무기가 다른 UI나 소품에 가리지 않아야 한다. 캐릭터를 아주 작게 두고 풍경만 크게 만드는 것은 불가다.
- 머리가 큰 둥근 장난감 비율, 부드러운 표면과 접지 그림자를 맞춘다. 원통·상자 몇 개로만 보이는 현재 조형을 그대로 둔 채 배치 완료로 처리하지 않는다.
- 기존 `UnitModel`에서 시작하되, 기준 이미지의 실루엣·소품·얼굴 읽힘에 도달하도록 로비용 모델 디테일과 재질을 보완한다. 기존 모델 재사용만으로 기준을 달성하지 못하면 필요한 아트 작업을 구현 목록에 포함한다.
- 로비용 모델·메시·재질 변형은 전투용 공유 리소스를 오염시키지 않게 한다. `Mats.shared()` 등에서 받은 공유 재질을 직접 바꾸지 말고 필요하면 로컬 복제/로비 전용 인스턴스를 사용한다.
- 전투 중 착용 장비를 로비에 이미 반영하는 경로가 있다면 유지한다. 임시로 모든 영웅의 실 저장 장비를 강제로 변경하지 않는다.
- 카메라는 기존 `(0, 4.6, 8.6)`와 기존 look-at을 정답으로 고정하지 않는다. 화면에서의 얼굴·발·상자 위치로 맞춘다. 과한 탑다운과 원근 왜곡을 피한다.

### 7.5 모닥불·보상 상자·보상 라벨

- 모닥불은 세 영웅 앞쪽, 상자는 오른쪽 전경. 뚜껑이 둥근 나무 상자, 얕은 금속 띠, 작은 자물쇠, 따뜻한 접지 그림자를 갖춘다.
- 불은 주황·노랑 두세 층의 부드러운 형태, 미세한 흔들림·소수의 불씨 정도. 강한 흰 bloom이나 화면을 뒤덮는 파티클은 피한다.
- 상자 위에는 크림색 `보상 받기` 알약과 작은 빨간 점. 라벨과 상자에 대응하는 큰 입력 영역을 연결한다.
- 입력은 기존 `_open_camp()`로 `CampScreen`을 연다. **실제 지급은 그 화면의 기존 받기 흐름**을 유지한다. 상자 탭과 화면 열기 양쪽에서 중복 지급하지 않는다.
- 상자 라벨은 표시·진입용이며, 로비가 별도로 `Meta` 재화를 증가시키지 않는다. 빠른 정비와 기존 무료 횟수도 보상 화면에서 유지한다.
- 실제 수령 가능 여부는 `Meta.camp_reward(Meta.camp_minutes())` 중 양수 보상이 있는지로 판단한다. 빨간 점의 주의 환기는 현재 로비 기준인 `camp_minutes() >= 60` 또는 `camp_full()`을 유지한다. 작은 보상을 받을 수 있는 상태와 빨간 점 조건을 혼동하지 않는다.
- 보상 0이면 상자 진입은 가능하게 두고 라벨은 `보상 쌓는 중`으로 약하게 표시한다. 보상이 있으면 `보상 받기`, 가득 찼으면 같은 라벨과 보상 화면 내 기존 가득 상태를 보여준다. 상자 진입 자체를 막아 기존 빠른 정비를 사용할 수 없게 만들지 않는다.
- 보상 라벨은 3D 상자 위의 앵커를 화면 좌표로 투영해 따라가게 한다. 3D viewport와 UI가 다른 크기면 좌표 변환을 포함한다. 화면 크기 변경, 팝업 복귀, 카메라 미세 움직임 후에도 상자와 라벨이 떨어지지 않아야 한다.
- 상자와 라벨 입력 영역은 합쳐서 한 동작으로 처리하고, 얼굴·챕터 시트·우측 버튼을 가로막지 않는다.

### 7.6 미션·출석 바로가기

- 오른쪽에 같은 크기의 크림색 라운드 버튼 두 개만 세로로 배치한다.
- 위는 클립보드와 초록 체크 + `미션`, 아래는 빨강 바인딩 달력 + `출석`. 그림과 글자는 각각 중앙 정렬한다.
- `_open_mission()` → `MissionScreen`, `_open_attend()` → `AttendScreen`으로 연결한다.
- 미션은 일일·주간 전환, 활동 점수 보상 등 기존 기능을 보존한다. 출석 날짜·수령·자동 열림 규칙도 유지한다.
- 미션·출석에 수령할 것이 있어도 과거의 기울어진 큰 `받기!` 리본은 다시 만들지 않는다. 컨셉의 상시 화면에서는 빨간 점을 추가하지 않고, 필요하면 아이콘 내부의 작은 체크나 화면 내부 상태로 표시한다.
- 현재 `_attend_shown`에 따른 자동 출석 팝업은 별도 승인 없이 제거하지 않는다. 정적 비교 캡처는 팝업이 없는 로비 상태로 촬영하고 자동 팝업 동작은 별도로 검증한다.

### 7.7 원정 시트와 모드 탭

- 하단에 하나의 넓은 따뜻한 크림색 시트를 놓는다. 윗모서리는 크게 둥글게, 그림자는 얕게. 진한 외곽선이나 밤색 이중 테두리는 쓰지 않는다.
- 중앙 상단에 청록색 `원정` 탭이 살짝 걸친다. 왼쪽에 단순한 흰색 접힌 지도 아이콘, 오른쪽에 짧은 글자.
- 이 탭은 현재 기본 모드를 알려주는 표시다. 별도의 새 모드 선택 팝업을 만들지 않는다.
- 장면 위를 덮는 면적은 이미지처럼 하단 약 1/3 안에 정돈한다. 캐릭터 무릎 위까지 시트가 올라오지 않아야 한다.

### 7.8 챕터 선택과 목표

- 크림색 오목한 챕터 줄 안에 왼쪽 화살표, 중앙 챕터명, 오른쪽 화살표를 배치한다.
- 챕터명은 `Meta.chapter_name(Meta.chapter)`를 사용한다. 예시 `1. 햇살 왕국`을 고정하지 않는다. 회차 접미사 등 현재 함수가 반환하는 문구도 처리한다.
- 현재 `_pick_chapter(step)`의 범위 `0..Meta.cleared`와 선택 저장 동작을 유지한다. 현재 열린 마지막 챕터 이상은 선택되지 않아야 한다.
- 첫 챕터에서는 왼쪽, 마지막 열린 챕터에서는 오른쪽 화살표를 실제 disabled로 처리한다. 회색 표현·입력 상태가 일치해야 하며 눌린 척 소리만 나지 않게 한다.
- 설명은 짧은 한 줄을 기본으로 한다. 컨셉의 `10무리 돌파`는 `Regions.PER_REGION`과 현재 챕터 구조에 맞춰 만들고, 클리어한 챕터를 다시 고르면 `클리어 완료` 같은 구분 가능한 문구를 사용한다.
- 긴 챕터명은 제목 영역 안에서 크기를 제한적으로 줄이고 필요하면 두 줄로 배치한다. 화살표를 밀거나 값이 버튼 위에 겹치지 않게 한다.
- 챕터를 바꿔도 홈 캠프 전체를 다른 테마로 새로 만드는 기능은 이번 필수 범위가 아니다. 선택한 값과 실제 출발 챕터의 일치를 우선 보장한다.

### 7.9 출발 버튼

- 화면에서 가장 크고 강한 버튼. 밝은 노란 상면, 부드러운 상단 반사, 얕은 주황 아래 턱, 짙은 남청 글자와 오른쪽 삼각형.
- 문구는 `출발`. 이미지처럼 글자와 삼각형을 하나의 중앙 묶음으로 정렬한다.
- 기존 `_go("march", true)`에 연결한다. 원정 여부는 `Meta.expedition`의 기존 설정 흐름을 따른다.
- 최초 입력 즉시 재진입을 차단하고, 기존 `_leaving` 가드·음향·전환을 활용한다. 손가락 연타나 마우스 더블클릭으로 미션 카운트·씬 이동이 중복되지 않아야 한다.
- 보상·설정·기타 화면이 열려 있을 때 배경의 출발이 눌리지 않아야 한다.
- 활성/눌림/비활성은 실제 버튼 상태와 일치시킨다. 눌림은 약간 아래로 들어가는 정도이며, 과도한 탄성으로 레이아웃을 흔들지 않는다.

### 7.10 끝없는 행군 링크

- 출발 아래에 작은 옅은 민트 알약, `끝없는 행군` + 오른쪽 chevron.
- 원정 버튼과 경쟁하는 두 번째 대형 카드로 만들지 않는다. 최고 기록 설명과 긴 소개 문장은 이 홈 화면에서 생략한다.
- 기존 `_go("march", false)`에 연결한다. 선택 중인 원정 챕터의 상태가 행군 시작 조건으로 잘못 섞이지 않아야 한다.
- 보이는 링크는 얇아도 실제 입력 영역은 충분히 크게 만든다. 출발 버튼과 하단 내비게이션에 터치 영역을 겹쳐 확장하지 않는다.

### 7.11 하단 내비게이션

화면 바닥에 크림색의 둥근 상단 모서리를 가진 고정 바. **왼쪽부터 정확히 장비 / 유물 / 캠프 / 도전 / 성장** 순서다.

| 항목 | 그림 | 동작과 선택 상태 |
|---|---|---|
| 장비 | 검 + 작은 방패 | 기존 `_open_gear()`로 이동. 합성 가능 시 작은 빨간 점 |
| 유물 | 받침 위 보라 수정 | 기존 `_open_relic()`로 이동 |
| 캠프 | 모닥불 | 홈 로비 자체. 기본 청록색 라운드 선택 배경 + 흰 라벨. 이미 홈이면 눌러도 팝업을 추가하지 않음 |
| 도전 | 교차한 검 | 기존 `_open_raid()`로 보스 토벌 화면 진입 |
| 성장 | 초록 새싹/나무 | 기존 `_open_talent()`로 골드 탤런트 화면 진입 |

- `캠프` 탭과 상자의 `보상 받기`는 역할이 다르다. 캠프 탭은 홈 위치를 나타내고, 상자가 방치 보상 화면을 연다.
- `도전`은 이번 구현에서 기존 토벌의 명칭·진입을 묶는 메뉴다. 행군은 이미 별도 링크에 있으므로 새로운 도전 허브를 필수로 만들지 않는다.
- 기존 화면은 로비 위의 화면/팝업으로 열 수 있다. 하단 바를 그 화면 안에 억지로 중복 삽입하지 않는다. 닫고 돌아오면 홈의 캠프 선택 상태를 복원한다.
- 아이콘 위, 라벨 아래를 같은 기준선에 정렬한다. 기본 그림 크기는 약 64~72, 중앙 캠프는 약 76~84. 탭 칸은 균등하게 분할하고 전체 높이는 입력 가능하게 만든다.
- 선택 청록색 배경은 중앙에만 둔다. 비선택 4개까지 모두 진한 색의 버튼 판으로 만들지 않는다.
- 장비 알림은 `Meta.merge_ready() > 0`에 연결한다. 컨셉의 빨간 점을 보이게 하려고 테스트 수치를 실 저장에 주입하지 않는다.
- 유물 합성/장착 가능, 성장 가능, 토벌 잔여 횟수의 정보는 기존 화면에서 계속 제공한다. 홈에서는 추가 리본을 만들지 않는다.

## 8. 아이콘·배경·모델 자산 완성 기준

컨셉 한 장을 전체 화면 배경으로 깔고 투명 버튼만 얹는 방식은 불가하다. 다음 요소는 서로 독립적으로 렌더링·교체·상태 변경이 가능해야 한다.

| 자산 묶음 | 필요한 결과 |
|---|---|
| 재화 | 금색 동전, 파랑 돌, 보라 결정의 정돈된 개별 아이콘 |
| 상단/보조 | 톱니, 클립보드 체크, 달력 |
| 원정/입력 | 접힌 지도, 좌우 chevron, 출발 삼각형 |
| 내비게이션 | 검·방패, 유물 받침·수정, 모닥불, 교차검, 새싹 |
| UI 표면 | 크림 시트·캡슐·노랑 버튼의 재사용 가능한 StyleBox/9-slice/텍스처 |
| 캐릭터 | 워리어·레인저·메이지 각 독립 모델·재질·대기 동작 |
| 캠프 | 잔디·나무·꽃·버섯·수정·바위·모닥불·보상 상자 |
| 원경 | 하늘·구름·절벽·물길·먼 성을 거리층으로 나눈 장면 |

- 이미지의 글자·수치·빨간 점을 자산에 구워 넣지 않는다.
- 아이콘은 이모지나 시스템 글리프로 대체하지 않는다. Windows와 Web에서 모양이 달라지지 않게 한다.
- 기존 `Hud.CoinIcon`, `Hud.StoneIcon`, `Hud.GemIcon`, `CalendarIcon`, `ClipboardIcon`, `GearIcon`, `CampScreen.FireIcon`은 연결·형태의 출발점이다. 크기만 키워 사용해도 컨셉 품질에 도달하는지 실제로 확인한다. 부족하면 정돈된 별도 아트를 만든다.
- 래스터 아이콘이면 투명 배경과 가장자리 품질을 확인하고 표시 크기보다 충분한 해상도를 준비한다. UI 스케일과 필터링 때문에 흐려지거나 흰 테두리가 생기지 않아야 한다.
- 고해상도 UI와 3D를 구분해서 최적화한다. 컨셉의 부드러운 모습을 내려다보는 카메라·아웃포커스 하나로 흉내 내다가 실제 UI까지 흐려지면 안 된다.
- 신규 런타임 자산은 `godot/` 내부에 두고 export 포함 여부를 확인한다. 문서용 `art/ui-concepts/` 경로의 파일이 자동으로 게임 리소스에 포함된다고 가정하지 않는다.

## 9. 움직임·음향·상태 갱신

- 영웅은 작은 호흡·고개·옷/무기 대기 동작을 사용한다. UI를 읽기 어렵게 만드는 큰 점프·화면 회전은 피한다.
- 현재 `_process()`의 `sin(_t * 0.25) * 0.5`처럼 섬 전체가 크게 돌아가는 동작은 새 구도에 맞게 중단하거나 아주 작게 줄인다. 대기 중에도 얼굴과 상자는 정해진 시각 영역에 머물러야 한다.
- UI 등장은 짧은 페이드·아래에서 8~16 정도 이동하는 수준으로 통일한다. 팝업을 닫을 때마다 모든 메뉴가 0배 크기에서 튀어나오지 않게 `_quiet_reload` 의도를 유지한다.
- 버튼 눌림은 약 80~160ms, 복귀는 약 130~220ms 범위에서 정돈한다. 연속 입력 시 이전 트윈을 취소해 변형이 쌓이지 않게 기존 `_press_tween` 원칙을 활용한다.
- 빨간 점은 기본 정지 상태. 모든 알림이 동시에 확대·축소하거나 흔들리지 않게 한다.
- 로비 BGM과 기존 클릭·출발·수령 소리를 유지한다. 버튼마다 새 음원을 겹쳐 재생하지 않는다.
- 기본 화면에서 대사 말풍선은 없어도 된다. 기존 `Chatter`를 유지하면 캐릭터 얼굴·미션/출석·재화·보상 라벨을 침범하지 않는 영역과 빈도로 제한한다. 비교 캡처에서는 대사가 없는 상태를 별도로 남긴다.
- HUD·배지 갱신은 팝업 복귀, 챕터 변경, 실제 재화 변경 시 즉시 수행한다. 방치 보상 대기는 1초 정도 간격으로 가용 상태만 갱신해도 된다. 매 프레임 로비 전체 노드를 재생성하지 않는다.
- 자정의 출석/미션 상태 전환은 기존 `Meta` 판단을 사용한다. 로비가 자체 날짜 규칙을 만들지 않는다.
- 팝업 열림 상태에서는 배경 버튼 입력을 차단한다. 닫을 때 불필요한 보상 재지급·챕터 초기화·대기 타이머 초기화가 없어야 한다.

## 10. 레이어·입력·수명 관리

1. 배경/원경 → 3D 캠프/영웅 → 보상 라벨 → 기본 로비 UI → 모달 딤과 기존 화면 순서로 겹친다.
2. 장식용 `Control`은 입력을 가로채지 않게 한다. 실제 버튼만 입력을 소유한다.
3. 외부 화면은 한 번에 하나만 열리게 `_gear`, `_relic`, `_daily`, `_settings`, `_leaving` 가드의 의도를 보존한다.
4. 기존 `_go()`는 `_settings`를 직접 검사하지 않는 부분이 있으므로, 새 View 입력 차단과 가드를 함께 검토해 설정 뒤의 출발이 작동하지 않게 한다.
5. 팝업을 닫을 때 레이어·신호·타이머를 정리한다. `_reload_quiet()`로 재생성할지 필요한 부분만 갱신할지는 선택할 수 있으나 중복 노드·음악·효과가 남지 않아야 한다.
6. 현재 자동 출석, 테스트 저장, 스크린샷 인자 처리는 새 View로 옮기는 과정에서 빠뜨리지 않는다.
7. 포인터가 보상 상자 위에 있어도 캐릭터를 조작하는 입력으로 전달되지 않게 한다. 이번 로비에서 영웅 탭으로 출전 인원을 바꾸는 기능을 추가하지 않는다.

## 11. Windows·Web 품질

- 우선 Windows Forward+에서 컨셉 구도를 완성한다. 현재 Web은 Compatibility와 `WebLookHook`을 사용하므로 밝기·그림자·색 차이를 별도로 확인한다.
- Web에서 지원되지 않는 후처리에만 의존하지 않는다. 배경의 깊이는 레이어·명도·대비로도 읽혀야 한다.
- 새 조명·재질이 기존 Web 보정 경로를 두 번 적용받거나 우회하지 않는지 확인한다. 로비 개선을 위해 공용 `WebLook` 계수를 바꾸어 전투 화면을 망가뜨리지 않는다.
- 복잡한 원경, 꽃, 잔디는 메시·재질 공유와 적절한 인스턴싱/배치로 관리한다. 창 크기 변경 때 같은 리소스를 계속 새로 만들지 않는다.
- 새 UI에서 첫 진입 시 긴 셰이더 컴파일·대형 텍스처 로딩이 늘면 실제 시간을 기록하고 원인을 줄인다. 보지 않은 디바이스에서 60fps라고 주장하지 않는다.
- 창 리사이즈 후 3D와 UI가 어긋나거나 글자만 비정상적으로 커지지 않아야 한다.

## 12. 권장 구현 순서

1. 현재 저장소 상태·기존 로비 캡처·주요 버튼 동작을 기록한다. 사용자 실 저장은 초기화하지 않는다.
2. 로비 전용 View와 스타일을 만들고 HUD·우측 버튼·원정 시트·하단 바의 고정 레이아웃부터 잡는다. 버튼은 실제 기존 화면과 연결한다.
3. 중앙 캠프 카메라·영웅 크기·전후 관계를 맞춘다. 이 단계에서 캐릭터가 작은 문제가 남으면 소품 작업 전에 해결한다.
4. 영웅 조형·나무·수정·모닥불·상자와 원경을 컨셉 품질로 보완한다. 분리된 아트 자산이 필요하면 함께 제작한다.
5. 보상 앵커, 동적 숫자·챕터명, 상태별 표시, 안전 영역·긴 화면 대응을 완성한다.
6. 눌림·대기·등장 모션과 음향을 정돈하고 팝업 복귀·중복 입력을 검증한다.
7. 실제 캡처를 컨셉 옆에 놓고 차이를 수정한다. 기능 체크만 통과했다고 중단하지 않는다.
8. Windows 빌드와 Web 영향 확인, 최종 캡처·변경 요약·남은 차이를 제출한다.

## 13. 검증 시나리오와 캡처

아래는 **구현자가 수행해야 할 검증**이다. 이 문서 작성 단계에서 구현 또는 테스트 완료를 주장하는 목록이 아니다.

### 13.1 정적 시각 검증

- 720 × 1280 논리 / 기본 540 × 960 창에서 컨셉과 비교.
- 360 × 640 상당의 작은 표시, 9:19.5 및 9:20 상당의 긴 세로 화면, 지원 대상의 넓은 화면에서 안전 영역·배치 확인.
- 같은 비율로 비교했을 때 얼굴 크기, 중앙 파티 위치, 시트 시작 위치, 주 버튼의 폭·명도, 원경의 대비가 컨셉과 유사한지 확인.
- 흐림 없는 한국어, 재화 0/큰 값, 긴 챕터명, 비활성 화살표, 기본/눌림/팝업 열림 상태 확인.
- 콜라주가 아닌 실제 게임 전체 캡처를 남긴다. 상태별 캡처 이름과 사용한 화면 크기·렌더러를 함께 기록한다.

### 13.2 기존 내장 캡처 경로 활용

현재 로비 `_ready()`는 `--shots=<폴더>` 인자를 받으면 테스트 저장을 사용하고 1.6초 뒤 `lobby.png`를 저장한 다음 종료한다. 자동 출석 팝업도 이 경로에서는 억제된다. **캡처 폴더는 먼저 만든다.**

프로젝트 루트에서 Windows 실행 파일을 확인할 예시:

```powershell
$shotDir = Join-Path (Get-Location) 'art/ui-concepts/2026-10-23-lobby/implementation/windows-home'
New-Item -ItemType Directory -Path $shotDir -Force | Out-Null
$shotArg = '--shots=' + $shotDir.Replace('\', '/')
& '.\TrioChess.exe' '--' $shotArg
```

원정으로 바로 진입하는 `--mode=march`나 `--autoplay`를 홈 캡처 명령에 섞지 않는다. 기능 화면 캡처는 현재 지원하는 `--open=gear`, `--open=relic`, `--open=settings`, `--open=mission`, `--open=raid`, `--open=daily`, `--open=talent` 경로를 각각 별도 폴더에서 활용할 수 있다.

새 레이아웃과 기존 캡처 보조 코드가 충돌하면 보조 코드를 갱신한다. 특히 현재 설정 캡처가 특정 `Button.text`로 개발용 버튼을 찾는 부분, 테스트 화면을 순서대로 열고 닫는 부분을 확인한다. 깨진 테스트를 무시하거나 게임 입력을 우회해 성공한 척하지 않는다.

### 13.3 기능 검증 표

| 시나리오 | 통과 기준 |
|---|---|
| 일반 실행 | 홈 정상 진입. 일일 최초 출석 자동 열림은 기존 규칙대로 작동 |
| 재화 표시 | 저장 값과 3개 HUD 값 일치. 예시 숫자 하드코딩 없음 |
| 장비 | 장착·해제·강화·합성 후 홈 복귀 시 갱신, 알림 상태 일치 |
| 유물 | 장착·합성 후 복귀 정상, 저장 보존 |
| 성장 | 기존 골드 탤런트 화면 진입·강화·재화 갱신 정상 |
| 미션 | 일일·주간·활동 보상 수령 후 상태 갱신, 중복 지급 없음 |
| 출석 | 가능/수령 완료 상태 및 날짜 판정 정상 |
| 모닥불 0 | 상자 진입 가능, 누적 중 표시, 기존 빠른 정비 접근 가능 |
| 모닥불 누적/가득 | 라벨·알림 조건 일치, 실제 지급은 기존 화면에서 정확히 한 번 |
| 시간 경과 | 홈에 머무른 상태에서 보상 가용 표시가 갱신됨 |
| 챕터 선택 | 0..cleared 범위, 끝 화살표 비활성, 선택 저장, 긴 이름 표시 정상 |
| 원정 출발 | 선택 챕터·원정 플래그가 실제 진행과 일치 |
| 끝없는 행군 | 원정 플래그 없이 기존 행군 시작 |
| 도전 | 토벌 화면 접근, 기존 티켓 차감과 실제 시작 흐름 보존 |
| 캠프 탭 | 현재 홈 유지. 방치 보상 팝업을 중복 생성하지 않음 |
| 설정 | 음량·닫기 정상. 배경 입력이 출발로 전달되지 않음 |
| 연타/닫고 재열기 | 팝업·음향·트윈·씬 이동 중복 없음, stale 버튼 없음 |
| 재실행 | 재화·장비·유물·챕터·일일 상태가 이전 규칙대로 저장됨 |
| 리사이즈 | 얼굴·상자·보상 라벨·HUD·시트·내비게이션 겹침 없음 |
| 프리셋 호환 | 기존 두 프리셋 저장 상태에서도 새 로비가 유지되고 다른 화면이 깨지지 않음 |
| Web | 한국어 표시, 버튼 입력, 과노출·심한 지연·리소스 누락 확인 |

테스트용 재화·진행도 조작은 기존 테스트 저장에서만 수행한다. 화면을 컨셉과 똑같은 숫자로 보이게 하려고 실 사용자 데이터를 바꾸지 않는다.

## 14. 빌드와 제출물

- 저장소 루트의 게임 산출물은 `TrioChess.exe`다. 코드만 고치고 오래된 실행 파일을 그대로 두지 않는다.
- 현재 문서화된 빌드 방법은 `godot/`에서 `python tools/build_exe.py`다. 설치된 Python 실행 명령과 엔진 경로는 실제 환경에서 확인한다.
- 이 빌드 스크립트는 기존 exe를 덮어쓰고 `godot/build/`의 일부 옛 빌드를 정리한다. 실행 중 파일 잠금과 보존할 산출물이 있는지 먼저 확인한다. 사용자 플레이 중인 프로세스를 임의로 강제 종료하지 않는다.
- Windows와 Web은 서로 다른 산출물이다. Windows 빌드만 갱신해 놓고 Web도 완료했다고 보고하지 않는다. Web 빌드를 갱신한 경우 기존 `Web` export 설정과 실제 브라우저 확인 결과를 함께 남긴다.
- 최소 제출: 변경 파일 목록, 사용한 신규 아트 경로, 새 Windows 실행 파일, 기본 로비·상태별 캡처, 실제 수행한 검증 결과, 컨셉 대비 남은 차이.
- 새 화면이 준비되면 실제 최신 실행 파일로 다시 실행해 확인한다. 원본 컨셉 이미지를 게임 캡처로 제출하지 않는다.
