# E 톤 UI/UX 재설계

## 목표와 근거

선택한 흑보라·라일락·라임 톤을 유지하면서 정보 구조와 행동 순서를 바꾼다. 게임 코드는 수정하지 않는 클릭 가능한 설계 시안이다. 재화·장비·진행 상태는 검토용 예시이며 실제 저장과 연결하지 않는다.

주요 게임 루프는 **원정 출발 → 자동 전투를 보며 스킬북·장비 판단 → 정산 → 영구 장비·슬롯 성장 → 재출발**로 정의한다. 실제 코드의 원정·행군, 장비와 슬롯 강화, 스킬북 사용 흐름을 확인했다. 이용 빈도·유저 조사 자료는 없으므로 아래 중요도는 설계 가설이다. UI 원칙이 전환율이나 잔존율 개선을 보장한다고 주장하지 않는다.

## 콘텐츠 중요도

| 영역 | 최우선: 지금 판단할 것 | 두 번째: 현재 과업을 돕는 것 | 필요할 때 열 것 |
|---|---|---|---|
| 로비 | 어느 모드·챕터로 출발하는가 | 파티의 장비·유물·탤런트 준비 | 출석·미션·모닥불 수령, 토벌, 설정 |
| 전투 | 적·영웅·공격의 공간적 상황, 파티 생존 | 스킬 준비 상태, 사용할 스킬북, 무리 진행 | 전체 가방, 개별 아이템·영웅 정보, 누적 특성·기록 |
| 장비 | 누구의 어느 부위를 바꾸며 무엇이 개선되는가 | 현재 착용품과 후보 비교, 필요한 비용 | 슬롯 강화, 합성, 판매, 긴 효과 설명 |

기준은 전투·진행에 미치는 영향, 현재 과업과의 관련성, 반복 사용 가능성이다. 토벌이 실제 주요 플레이 모드로 확인되면 모험 선택에 승격할 수 있다. 이 순위는 고정된 사실이 아니다.

## 화면별 변경

### 로비 — 파티를 본 뒤 출발한다

- 큰 로고와 양옆의 보조 버튼을 줄이고 캐릭터 무대를 깨끗하게 둔다.
- 원정/끝없는 행군을 한 모드 선택기 안에 묶고, 선택 모드에 대응하는 주 행동을 하나만 둔다. 원정에서는 챕터 선택이 바로 근처에 있다.
- 출발에 필요한 선택 정보 → 출발 버튼을 같은 카드에 둔다. 지원되는 체크포인트 재개 기능이 확인되지 않았으므로 ‘이어하기’를 만들지 않는다.
- 장비·유물·탤런트는 ‘파티 준비’로 묶되 각각 직접 진입할 수 있게 한다.
- 출석·미션·모닥불·토벌은 하단 ‘활동’의 한 단계 패널로 모은다. ‘수령 가능’만 배지로 알리고, 도전 가능하다는 이유만으로 빨간 배지를 붙이지 않는다.
- 하단 정보 구조는 모험 / 성장 / 활동. 기존 전투 화면의 미동작 상점·영웅·도감 버튼을 복사하지 않는다.

### 전투 — 필드 우선, 가방은 펼쳐서 판단한다

- 전역 내비게이션과 영구 재화 3종을 상시 전투 HUD에서 뺀다. 무리 진행·보스 접근·일시정지를 상단에 남긴다.
- **스킬 지름 58, 영웅 상태줄 높이 46(720 논리 폭 기준)을 고정한다.** 자동 발동 표시이므로 스킬 원에는 버튼 역할을 주지 않는다.
- 두 스킬과 해당 영웅을 같은 열에 두어 소속을 알아보기 쉽게 한다. 상태줄은 작은 얼굴 + HP·마나 + 레벨 한 줄이다. 영웅 상세를 여는 실제 터치 영역은 시각적 캡슐보다 크게 둔다.
- 가방 14칸을 상시 펼치는 대신 ‘가방 3/14’ 진입부와 ‘스킬북 사용’을 하단에 노출한다. 전체 가방은 한 단계 패널로 펼친다.
- 가방·아이템·영웅 정보를 읽는 동안에는 ‘일시정지’ 상태를 표시하고, 닫으면 복귀한다. 새 아이템 수령이 사용자의 선택을 가로채는 자동 팝업을 만들지 않는다.
- 특성·획득 기록은 일시정지 메뉴에 모은다. 스킬북이 없으면 사용 행동을 비활성화하고 이유를 표시한다.

### 장비 — 결과를 비교한 뒤 장착한다

- 직업 → 부위 → 보관함 후보 → 현재/후보 차이 → 장착의 순서로 배치한다.
- 장비 교체와 슬롯 강화를 모드로 나눈다. 세 부위의 강화 버튼이 장착 행동과 동시에 경쟁하지 않는다.
- 선택 부위로 보관함을 필터링하고, 비교 카드에는 현재값·후보값·차이를 함께 보여 준다. 등급만으로 무조건 더 좋다고 판정하거나 허구의 종합 전투력을 만들지 않는다.
- 예시: 낡은 검 공격력 5 → 강철검 12, 장비 공격력 +7. 값은 `defs.gd`에서 확인했다. 다른 효과도 비교에서 숨기지 않는다.
- 슬롯 강화는 아이템 강화와 구분한다. ‘장비를 바꿔도 유지’와 현재·다음 슬롯 보너스, 골드·강화석 비용을 같은 영역에 둔다. 비용은 기존 `Gear.upgrade_cost` 식을 사용한다.
- 합성은 보관함 도구, 판매는 선택 아이템의 추가 메뉴에 둔다. 합성·판매 결과를 미리 보여 주고 확인한다. 합성 규칙은 같은 부위·같은 등급 3개이며 결과 종류가 무작위임을 표시한다.

## 이론을 적용한 결정

| 원칙 | 이 시안의 결정 | 한계·검증할 점 |
|---|---|---|
| [시각적 위계](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/) | 라임은 그 상태의 주 행동에만, 라일락은 선택·내비게이션에 사용. 출발·장착의 크기와 대비를 높임. | 대비·크기가 실제 첫 시선과 행동을 유도하는지 확인해야 함. |
| [근접성](https://www.nngroup.com/articles/gestalt-proximity/) | 모드와 출발, 영웅과 해당 스킬, 아이템과 비교·장착을 가까이 배치. | 박스를 늘리기보다 간격·정렬로 묶음. |
| [점진적 공개](https://www.nngroup.com/articles/progressive-disclosure/) | 가방·활동·긴 설명을 한 단계로 펼침. 핵심 행동인 출발·스킬북 사용은 숨기지 않음. | 가방의 추가 진입 비용이 전투 중 빈번한 조작에 불리할 수 있음. |
| [회상보다 재인](https://www.nngroup.com/articles/recognition-and-recall/) | 현재 장비 수치를 기억하지 않아도 선택품과 나란히 비교. 가방 점유·책 수를 진입부에 유지. | 숫자 하나로 여러 효과를 지나치게 단순화하지 않음. |
| 상태 피드백·오류 예방 | 일시정지, 장착 완료, 재화 차감, 강화 불가 이유를 표시. 판매·합성은 결과 확인. | 클릭 시안의 동작 확인과 실제 플레이 검증은 구분. |

## 검토할 과업

1. 로비에서 원정 챕터를 바꾸고 출발한다. 보조 기능에 들어가지 않고 가능한가?
2. 활동에서 수령 가능한 항목을 찾고 수령한 뒤 모험으로 돌아온다.
3. 전투에서 스킬북을 쓰고, 가방에서 아이템을 읽고, 필드로 돌아온다. 정지·재개 상태를 이해하는가?
4. 장비에서 현재보다 공격력이 높은 검을 찾아 차이를 확인하고 장착한다.
5. 슬롯 강화로 전환해 장비와 슬롯의 차이, 비용과 다음 보너스를 설명할 수 있는가?

측정 후보: 과업 완료 여부, 첫 행동까지 시간, 잘못된 진입, 되돌아가기 횟수, 비용·효과 이해 여부. 이번 작업에서 실사용자 수치나 개선율을 만들어 내지 않는다.

## 파일

- `index.html`, `style.css`, `app.js`: 상태를 바꿔 볼 수 있는 실제 크기 UI 시안.
- `assets/`: 기존 아이콘·폰트와 새로 생성한 UI 없는 게임 배경.
- `prompts.json`: 내장 image_gen으로 생성한 배경의 전체 프롬프트.

로비 정보 구조, 가방 접기, 장비 비교·강화 모드 분리는 제안되는 UI 변경이다. 자동 발동·보상·저장·합성 판정 자체를 바꾸는 제안이 아니다.
